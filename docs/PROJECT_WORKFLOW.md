# Рабочий протокол Telanico

Зафиксировано по просьбе владельца 23 октября 2026. Это постоянный контекст для
следующих задач. Фактическое состояние Git, процессов и сайта нужно перепроверять.

## Изначальная схема

- Telanico-3D-Lab: приватные исходники, Blender, Godot, проверки и история.
- Включённая локальная Windows-машина: полноценная рабочая и сборочная среда.
  Повторно использовать установленный софт, кэш и существующую авторизацию GitHub.
- Облачная задача «Проверить облачный 3D-пайплайн» хранит выполненную работу:
  01a150fe-2a87-7318-8495-abad9be1705a. Ранее в ней проверены Blender 4.3.2 и
  Godot 4.6.3. Существование задачи не доказывает, что процесс сейчас выполняется
  или что локальному агенту доступен прямой shell её контейнера.
- Первоначальная автоматизация: приватный Actions → проверенный артефакт →
  публичный импорт → GitHub Pages. Actions не является единственным местом сборки.
- Telanico-3D-Web: существующие публичные runtime-файлы и Pages; приватные
  исходники, модели и журналы здесь не публикуются.
- Результат выпуска: нужная версия по публичной ссылке, проверенная после
  публикации. Код, PR, локальный экспорт, успешный CI и live — отдельные состояния.

## Ошибки процесса

1. Первый статус был составлен по старой локальной second-office-smoke без
   основной облачной задачи, PR и live-метаданных. Выполненная работа ошибочно
   называлась будущими этапами.
2. README утверждал отсутствие деплоя, а инструкция обещала уже отключённый
   импорт каждые десять минут. Исторические инструкции не были помечены как старые.
3. Отсутствие команды в PATH и ограничение коннектора слишком рано трактовались
   как отсутствие инструментов/доступа вообще. Инвентаризация должна предшествовать
   новым загрузкам и настройке.
4. Godot 4.6.3 и Web-шаблон были заново получены для совпадения с облачной версией.
   Это дало рабочий билд, но сначала следовало проверить существующую среду/кэш.
   Найденный локальный 4.7.2 не доказывал отсутствие готового 4.6.3 в облаке.
5. Приватные Actions повторялись без точного текста отказа. Существующая локальная
   авторизация позволила прочитать annotations: ограничение оплаты/расходов.
   Ноль выполненных шагов не мог быть следствием игрового Contracts.
6. Переключения между коннекторами, браузером, другой задачей и локальной настройкой
   раздули количество запросов и нагрузку на владельца. Следовало раньше выбрать
   один пригодный существующий путь и пройти его до live.
7. Реальные игровые ошибки были исправлены ранее. Их нельзя смешивать с отказом CI
   или превращать выпуск в бесконечную разработку и расширение проверок.

## Порядок дальнейшей работы

1. Восстановить контекст: AGENTS, этот файл, текущий PR/кандидат, логи, состояние
   активных процессов и публичный build.json. Открытая локальная ветка — лишь часть.
2. Найти известные исполняемые файлы, версии, шаблоны, кэши и готовые runtime-сборки.
   Использовать имеющиеся Python/Node и авторизацию. Не скачивать софт по умолчанию.
3. Выбрать уже пригодную среду. Использовать включённую локальную машину; если
   точная рабочая сборка уже есть в доступном облаке — использовать её. Передавать
   код/артефакт явно, сохраняя SHA и происхождение. Не считать окружения автоматически
   общими. Не поручать работу другой задаче без разрешения владельца.
4. Установить слой сбоя: команда/PATH, sandbox, зависимость, игра, экспорт, runner,
   импорт, Pages или live. Читать конкретные ошибки/annotations. Повторять запуск,
   только когда есть причина ожидать иной результат.
5. Для промежуточного релиза заморозить новые функции. Исправить блокер; если владелец
   разрешил, отключить подтверждённо сломанный блок с сообщением игроку и записью
   ограничения. Не отключать рабочий Contracts и не ослаблять проверки молча.
6. Проверить затронутую функциональность и экспорт. Не создавать заново полную
   матрицу всех устройств для каждого выпуска. Различать дефект игры, сбой тестового
   окружения и согласованное ограничение; не выдавать упавший тест за успешный.
7. Опубликовать в прежний Telanico-3D-Web, дождаться Pages, проверить HTTPS-версию
   и desktop/мобильный интерфейс. Сохранить SHA, ссылки, результаты и возможность отката.

## Доступы и подтверждения

Разрешение владельца на выпуск включает обычные необходимые правки, проверки,
коммиты, push и публикацию по существующей схеме. Не спрашивать об этом повторно
в разговоре. Не создавать новые токены, сервисы или окружения, когда имеющиеся подходят.

Отдельно действует принудительная политика Codex: в этой сессии сеть ограничена,
а .git защищён от записи внутри sandbox. Некоторые команды поэтому вызывали
системные approvals при уже работающей GitHub-авторизации. Это не новый доступ к
аккаунту. Повторно использовать применимые сохранённые правила команд и подходящие
имеющиеся инструменты. Не обходить запреты, не ослаблять защиту и не обещать
устранить системные approvals записью в AGENTS. Настройки безопасности не менялись.

Официальные пояснения:
https://learn.chatgpt.com/docs/agent-approvals-security
https://learn.chatgpt.com/docs/agent-configuration/agents-md
